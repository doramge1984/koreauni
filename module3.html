Overview

한눈에 보기 — 무엇을 · 왜 · 어떻게

"가평 가자!" 하고 감으로 정하면 절반은 시큰둥합니다. 흩어진 의견을 데이터로 모아 차트로 보면, 모두가 납득하는 장소와 날짜가 보입니다.

🎯

무엇을 (What)

구글 폼 응답이 쌓인 시트를 실시간으로 불러와, KPI와 차트가 살아있는 '결정 대시보드'를 만듭니다.

💡

왜 (Why)

데이터로 정하면 "왜 거기?"라는 뒷말이 사라집니다. 과대표·총무의 의사결정에 설득력이 생깁니다.

⚙️

어떻게 (How)

폼·시트 → 앱스 스크립트(Apps Script)가 JSON API로 배포 → Gemini Canvas가 그 주소를 불러와 시각화. 앱스 스크립트가 뭔지는 바로 아래에서 설명합니다.

핵심 메시지 — '보는 것'과 '결정하는 것'의 차이

📊 응답이 쌓인 시트 보기

같은 데이터라도 어떻게 보느냐에 따라 결정이 달라집니다. 인기 장소 1위, 가장 많이 되는 날짜, 적정 예산을 한 화면에서 보고 — 감이 아니라 숫자로 MT를 정합니다.

앱스 스크립트(Apps Script)란?

모듈 3과 모듈 4에서 함께 쓰는 도구입니다. 처음 보셔도 괜찮아요 — 네 가지만 알면 충분합니다.

눌러서 설명 보기
1

구글 안에 들어있는 자동화 도구

따로 설치하지 않습니다. 구글 시트·폼·문서·슬라이드 안에 이미 들어 있고, 구글 계정만 있으면 바로 열립니다.

2

구글 앱들을 대신 조작합니다

시트를 읽고, 문서를 만들고, 드라이브에 저장하고, 메일까지 보냅니다. 사람이 손으로 하던 일을 내가 넣은 코드가 대신합니다.

3

알아서 실행됩니다

내가 버튼을 누를 때는 물론, 폼에 응답이 들어오는 순간이나 매일 정해진 시간에 저절로 실행되게 걸어둘 수 있습니다.

4

내 데이터에 주소를 붙여줍니다

앱스 스크립트에서 웹 앱으로 배포하면 주소 하나가 생깁니다. 대시보드는 그 주소로 찾아와 데이터를 가져갑니다. 이 주소를 API라고 불러요.

설치 없음구글 계정만 있으면 됨무료코드는 교안에 준비됨
💬 이 주소가 왜 필요한가요? API와 JSON 이야기

구글 시트에 쌓인 답을 대시보드가 읽으려면 읽을 수 있는 주소가 하나 있어야 해요. 그 주소를 APIApplication Programming Interface라고 부릅니다. 프로그램끼리 데이터를 주고받는 통로라는 뜻이에요.

그런데 주소가 데이터를 담아서 보내는 방식은 여러 가지가 있어요. 그중 많이 쓰는 두 가지를 비교해 볼게요.

  • 시트를 그냥 공개해서 만든 주소는 보통 → 쉼표로 죽 이어붙여 보냅니다
  • 오늘 우리가 만들 API 주소는 → 값마다 이름표를 붙여 보냅니다
쉼표로 죽 이어붙이기 CSV 김민준,가평,2학년

답 안에 쉼표가 들어 있으면 칸이 밀립니다.
구글 폼 체크박스는 답을 가평, 강촌 처럼 쉼표로 붙여 저장하기 때문에, 이 문제가 실제로 생깁니다.

값마다 이름표를 붙이기 JSON 이름: 김민준 / 장소: 가평 / 학년: 2학년

값에 이름표가 붙어 있어서 칸이 밀릴 일이 없습니다. 답 안에 쉼표가 있어도 그대로 전달됩니다.

② 폼 게시하기 — 이걸 안 하면 아무도 응답할 수 없어요

사본으로 만든 폼은 아직 게시되지 않은 상태입니다. 이대로 링크를 보내면 학우들이 폼을 열 수 없어요.

  • 폼 우측 상단의 게시 버튼 클릭
  • 응답할 수 있는 사용자를 링크가 있는 모든 사용자로 변경
  • 게시 → 이어서 응답 링크 복사로 주소를 받아 둡니다
💡 복사한 응답 링크는 5단계 실시간 동기화 테스트에서 씁니다.

앱스 스크립트(Apps Script)로 내 데이터 창구(API) 만들기 Apps Script

🎯 시트 데이터를 실시간으로 내보내는 공개 API 주소

💡 앱스 스크립트(Apps Script)가 처음이어도 걱정 마세요. 어려운 코드는 이미 다 써뒀어요 — 여러분은 복사해서 붙여넣고 배포만 하면 '데이터 창구(API)'가 뚝딱 생깁니다.

① 코드를 못 짜도 괜찮아요 — Gemini에게 코드를 받아옵니다

✨

Gemini 프롬프트 · 데이터 창구(API) 코드 받아오기

이 프롬프트 하나로 아래 ②의 doGet 코드가 만들어집니다.

구글 시트에 쌓인 설문 응답을 웹 대시보드가 바로 읽을 수 있도록, JSON으로 내보내는 Apps Script를 만들어줘.

[필수 조건]
1. doGet(e) 함수로 만들고, 웹 앱으로 배포하면 주소 하나로 데이터를 받아볼 수 있게 해줘.
2. 현재 스프레드시트의 첫 번째 시트를 읽고, 첫 행은 헤더(항목 이름), 나머지 행은 응답 데이터로 나눠줘.
3. 각 행을 헤더 이름을 키로 갖는 객체로 바꿔서 전체를 JSON 배열로 반환해줘. (쉼표로 이어붙이는 CSV가 아니라 JSON이어야 해)
4. 값이 날짜·시간이면 Asia/Seoul 기준 문자열로 바꿔줘.
5. 완전히 빈 행은 결과에서 빼줘.
6. ContentService로 MimeType.JSON을 지정해서 반환해줘.
7. 코드 각 줄에 무슨 일을 하는지 한국어 주석을 달아줘.
📖 설명 글로 보기

아래 코드는 제가 직접 타이핑한 게 아니라, Gemini에게 시켜서 받은 것입니다. 프롬프트를 그대로 붙여넣으면 바로 아래 ②에 들어갈 코드가 거의 완성된 형태로 나옵니다. 오늘 진짜 배울 건 코드 문법이 아니라, 필요한 자동화를 AI에게 정확히 주문하는 법이에요.

💡 주문서에 꼭 들어가야 할 세 가지예요.
  · 어디서 읽을지 — 현재 스프레드시트의 첫 번째 시트
  · 어떤 모양으로 만들지 — 헤더 이름을 키로 갖는 JSON 배열
  · 어떻게 내보낼지 — doGet + 웹 앱 배포 + MimeType.JSON
→ 이 세 개를 빼먹으면 엉뚱한 코드가 나옵니다. 반대로 이 세 개만 정확하면 거의 그대로 작동하는 코드가 나와요.
🔨 코드가 예상과 다르게 나와도 괜찮아요. 에러 메시지를 그대로 붙여넣거나 이 부분이 이렇게 안 돼, 이렇게 바꿔줘처럼 대화하듯 고쳐나가면 됩니다. 오류를 잡는 과정도 AI와 함께 하는 거예요.

Apps Script · doGet (JSON API)

시트 데이터를 헤더 키가 붙은 JSON 배열로 반환합니다.

function doGet(e) {
  // 1. 현재 스프레드시트의 '첫 번째 시트'를 가져옵니다.
  //    ※ 응답 시트가 맨 앞에 있어야 해요. 빈 '시트1'이 앞에 있으면
  //    아래를 getSheetByName('설문지 응답 시트1') 로 바꿔주세요.
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];

  // 2. 데이터가 있는 전체 범위를 2차원 배열로 가져옵니다.
  const data = sheet.getDataRange().getValues();

  // 3. 첫 행은 헤더, 나머지는 응답 데이터로 분리합니다.
  const headers = data[0];
  const rows = data.slice(1);

  // 4. 각 행을 '헤더 이름을 키로' 갖는 JSON 객체로 변환합니다.
  const result = rows
    .filter(row => row.join('').trim() !== '') // 빈 행 제외
    .map(row => {
      let obj = {};
      headers.forEach((header, index) => {
        if (row[index] instanceof Date) {
          obj[header] = row[index].toLocaleString('ko-KR', { timeZone: 'Asia/Seoul' });
        } else {
          obj[header] = row[index];
        }
      });
      return obj;
    });

  // 5. JSON 형식으로 웹에 반환합니다.
  return ContentService.createTextOutput(JSON.stringify(result))
    .setMimeType(ContentService.MimeType.JSON);
}
💡 이 코드는 구글이 내 시트 안에서 실행하는 내 코드예요. 외부에 데이터를 보내는 게 아니라, 내 시트를 읽어 JSON으로 보여줄 뿐이라 안전합니다.

③ 웹 앱으로 배포해서 API 주소 받기

  1. 앱스 스크립트(Apps Script) 화면 우측 상단 파란색 [배포] → [새 배포]를 클릭합니다.
  2. 톱니바퀴(설정) 아이콘을 눌러 유형을 [웹 앱]으로 선택합니다.
  3. 가장 중요! '액세스 권한이 있는 사용자'를 반드시 '모든 사용자(Anyone)'로 변경합니다. (이걸 안 하면 대시보드가 데이터를 못 읽어요.)
  4. 파란색 [배포]를 누릅니다.
  5. 최종 화면의 '웹 앱 URL'을 복사해 메모장에 임시로 저장합니다.

Gemini Canvas로 'MT 결정 대시보드' 만들기 Gemini Canvas

🎯 KPI + 차트가 살아있는 예쁜 단일 페이지 대시보드
  1. 제미나이 창을 열고 Canvas를 켭니다.
  2. 아래 프롬프트를 복사하되, [웹 앱 URL] 부분만 4단계에서 메모한 내 주소로 바꿉니다. (아래 박스에 붙여넣고 버튼을 누르면 자동으로 들어가요!)
  3. 붙여넣고 실행합니다.
✅ 아래 프롬프트의 [웹 앱 URL] 자리에 들어갔어요.
🗣️

프롬프트 · 실시간 대시보드 (예쁨 강화판)

🔴 빨강 = 열 매칭·집계 규칙 · 🟢 초록 = 데이터·실시간 규칙 · 🔵 파랑 = 디자인(바꿔도 OK) — 빨강·초록은 꼭 유지!

나는 구글 폼 응답을 앱스 스크립트(Apps Script)로 JSON API로 배포했어. API 주소는 '[웹 앱 URL]' 이야.
이 API를 fetch로 불러와, 과대표·총무가 'MT 장소와 날짜'를 데이터로 결정하는 실시간 대시보드를 HTML/CSS/JS 단일 파일로 만들어줘.

[데이터 · 실시간 규칙 — 반드시 지킬 것]
- API 주소 끝에 '?t='+Date.now() 를 붙여 fetch 해서 브라우저 캐시를 피하고, 30초마다 다시 불러와 KPI·차트를 갱신해줘.
- 응답은 이미 [{헤더: 값}] JSON 배열이야. 각 값을 '원문 그대로' 쓰고, 임의로 만들거나 줄이거나 바꾸지 마. 하드코딩·샘플 데이터 금지.
- '참석 여부'가 '불참'인 행은 총 응답에는 포함하되, 장소·일정·학년·성향 차트 집계에서는 제외해. 빈 값은 세지 마.
- 불러오기에 실패하면 예시 차트를 그리지 말고, 빨간 오류 박스로 이유(주소·배포 권한 확인)를 보여줘.

[열 매칭 · 집계 규칙 — 반드시 지킬 것]
- 각 항목은 아래 헤더(키) 이름으로 정확히 읽어줘: 이름 / 참석 여부 / MT 희망 장소 / 학년 / MT 희망 일정 / MT 참불 및 늦참 여부 / 음주 성향 / 체력·숙소 성향
- 총 응답 수는 '이름'이 비어있지 않은 행만 세줘.
- '정시 참석 인원'은 'MT 참불 및 늦참 여부' 값이 정확히 '정시 참석 (금요일 출발)'인 행만 세줘.
- 카테고리는 값이 정확히 일치하는 것끼리만 묶어줘. 부분 매칭·임의 축약 금지.

[검증 표시] 상단 상태 영역에 [총 응답 수 / 참석·미정·불참 수 / 차트 집계 대상 수 / 마지막 새로고침 시각]을 보여줘. 차트 그리기 전에 console.log로 [전체 rows, 집계 대상 rows, 장소별 집계, 참석/미정/불참 집계]도 출력해줘.

[상단 KPI 카드]
① 총 응답 수(참석/미정/불참 분리) ② 1위 희망 장소 ③ 다 되는 날(최다 일정) ④ 정시 참석 인원

[차트 — Chart.js, 값/퍼센트 라벨과 범례 포함]
1. 인기 희망 장소 순위 (가로 막대, 인원 라벨)
2. 일정별 가능 인원 (세로 막대)
3. 학년별 참석 분포 (도넛)
4. 음주 성향별 인원 (파이)

[인사이트] 각 차트 아래에 '과대표가 이 데이터로 무슨 결정을 내리는지' 한 줄씩. 맨 아래에 1위 장소 + 다 되는 날 + 정시/늦참 인원을 조합한 '데이터 기반 최종 추천' 카드.

[디자인] 딥네이비 배경에 시안·민트·코랄 포인트의 밝고 화사한 카드형 대시보드로 만들어줘. 그라데이션 헤더, 둥근 카드, 부드러운 그림자, KPI 숫자는 크게, 이모지 포인트. 상단에 'LIVE 동기화 중 · 다음 새로고침 N초' 상태 바. 모바일에서는 KPI·차트가 1열로 자연스럽게 쌓이게. 긴 장소명도 가로 막대에서 다 보이도록 여백을 충분히 줘.
